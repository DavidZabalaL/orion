1. Objetivo y Arquitectura de Recepción en Orión

Orión es la plataforma central de administración de flota de Grupo Kabat (construida sobre Next.js en Vercel y PostgreSQL Serverless en Neon con Prisma ORM). Orión no reemplaza la plataforma del proveedor de GPS, sino que consume de forma automatizada las posiciones, velocidades y lecturas de odómetro para alimentar su propio modelo de datos y cruzarlos con todos los módulos operativos del sistema.

Este documento define exclusivamente las características técnicas de software, API, Webhooks y contrato de datos que debe cumplir un proveedor de GPS para conectarse a Orión sin modificar las reglas de negocio actuales.

1.1 Modelo de Datos de Recepción en Orión

Toda lectura recibida por Orión se valida y almacena en el modelo central de flota con la siguiente estructura técnica:

Entidad / Campo en Orión Tipo de Dato Uso directo dentro de la plataforma Orión
Unidad.numeroEconomico String (PK) Identificador maestro de la unidad en Grupo Kabat (ej. KAB-100). Toda posición se vincula a esta llave.
Unidad.idExternoGps Int / String (@unique) ID único del vehículo en la API del proveedor para cruzar el catálogo externo contra el numeroEconomico.
Unidad.kmOficial Int Odómetro maestro de la unidad. Se actualiza automáticamente con cada lectura GPS válida (no anómala).
PosicionGPS.lat / lng Decimal(9, 6) Coordenadas WGS84 con precisión de 6 decimales para el mapa en vivo, rutas y filtro geográfico.
PosicionGPS.velocidad Decimal(6, 2)? Velocidad instantánea almacenada en km/h para visualización en mapa e historial.
PosicionGPS.timestamp DateTime Instante exacto (UTC) en que se generó la lectura. Sirve para deduplicar, ordenar rutas y triangular TAG/Combustible.
PosicionGPS.fuente API | WEBHOOK Indica si la lectura entró por consulta periódica en lote (API) o por empuje en tiempo real (WEBHOOK).
PosicionGPS.kmReportado Int? Odómetro crudo en kilómetros enteros reportado por el proveedor al momento de la lectura.
PosicionGPS.kmValidado Int? Igual a kmReportado si la lectura supera las 3 validaciones de integridad (Capa 1); null si es anómala.
HuecoSenalGPS Tabla de auditoría Se crea automáticamente si transcurren > 15 minutos entre dos lecturas sucesivas de una misma unidad.

2. Modalidades de Conexión Soportadas (REST Batch y/o Webhook)

Debido a que Orión opera sobre infraestructura Serverless (con límite de ejecución de 60 segundos por invocación y base de datos con suspensión automática por inactividad), la plataforma del proveedor debe ofrecer al menos uno —e idealmente ambos— de los siguientes mecanismos de integración:

Opción A: API REST de Consulta en Lote (Batch Polling)

Un endpoint único que devuelva el último estado de todos los vehículos de la cuenta en una sola llamada HTTP (o paginado con tamaño de página ≥ 500 vehículos) y tiempo de respuesta < 2 segundos.

Restricción crítica: No es admisible una API que obligue a realizar 1 petición HTTP individual por cada vehículo (~116 llamadas secuenciales agotan el timeout serverless).

Opción B: Webhooks HTTP POST (Push en Tiempo Real)

Envío automático de peticiones POST (JSON) hacia un endpoint de Orión cada vez que las unidades transmiten nuevas lecturas.

Ventaja para Orión: Actualización inmediata en el mapa sin esperar al cron de 10 minutos, y cero consumo de base de datos cuando toda la flota está estacionada.

2.1 Requisitos de Autenticación y Seguridad de API

  • Para API REST (Pull): Autenticación mediante API Key en encabezado (Authorization: Bearer <TOKEN>) o endpoint de sesión por credenciales que devuelva un token con tiempo de expiración explícito (expiresInSeconds ≥ 3600s) para cachearlo en memoria entre ejecuciones tibias.
  • Para Webhooks (Push): Capacidad de enviar un encabezado de autorización (Authorization: Bearer <SECRET>) o firma criptográfica HMAC-SHA256 para que Orión valide la autenticidad del origen.

3. Datos Obligatorios por Lectura y Reglas Críticas de Integración

Para alimentar el contrato de ingesta de Orión, el proveedor debe entregar en cada lectura los siguientes campos:

Campo Requerido Tipo / Unidad Criticidad Regla Técnica en el Código de Orión
Identificador de Vehículo Int o String Obligatorio ID único e inmutable por unidad en la plataforma del proveedor, o bien devolución directa del numeroEconomico / placas / VIN para mapearlo contra la tabla Unidad.
Latitud (lat) Number (WGS84) Obligatorio Grados decimales con al menos 5–6 decimales (ej. 22.284512). Lecturas nulas se omiten.
Longitud (lng) Number (WGS84) Obligatorio Grados decimales con al menos 5–6 decimales (ej. -97.863124). Lecturas nulas se omiten.
Timestamp de Lectura String (ISO-8601 UTC) Obligatorio Debe ser la hora exacta en que el GPS capturó la posición, nunca la hora en que se consultó la API. Si la unidad está detenida y no ha reportado un punto nuevo, el timestamp no debe cambiar.
Odómetro Acumulado Number (km) Obligatorio Kilometraje total acumulado del vehículo (preferentemente en km; si se entrega en millas debe ser constante y documentado). Orión no calcula distancias sumando coordenadas; usa exclusivamente la diferencia de este odómetro.
Velocidad Instantánea Number (km/h) Obligatorio Velocidad al momento de la lectura (preferentemente en km/h; si es mph debe estar documentado).
Estado de Ignición / Motor Boolean Fase 2 Spec Indica si el motor está encendido (true/false). Requerido para alertas de ralentí y uso fuera de horario previstas en la especificación de Orión.
Horómetro Acumulado Number (horas) Deseable (Grúas) Horas totales de operación del motor. Permite automatizar el umbral de mantenimiento preventivo de grúas configurado cada 500 horas en Orión.
⚠️ Por qué el Odómetro Acumulado y el Timestamp Real son Indispensables en Orión

1) Deduplicación por timestamp: Antes de insertar, Orión verifica if (anterior && anterior.timestamp >= timestamp) return omitido. Si la API del proveedor maquilla el timestamp poniendo la "hora actual de consulta" cuando un vehículo lleva días apagado, Orión insertará lecturas falsas cada 10 minutos e impedirá que funcionen las alertas de unidades sin señal.
2) Distancia por diferencia de odómetro: Tanto en el mapa como en historial, checklists y combustible, Orión calcula la distancia recorrida en un periodo como MAX(kmValidado) - MIN(kmValidado) (la fórmula Haversine solo se usa para descartar anomalías, nunca para sumar kilómetros). Sin odómetro acumulado en la API, el kilometraje recorrido en Orión sería 0 km.

4. Reglas de Negocio de Orión que Consumen los Datos GPS

El proveedor debe garantizar que la calidad, frecuencia y precisión de sus datos cumplan con los umbrales exactos que tienen programados los módulos de Orión:

4.1 Sub-módulo G.1 — Filtro Automático de Integridad y Huecos de Señal

Cada punto entrante pasa por tres validaciones automáticas de integridad antes de guardarse en Orión:

  • Filtro 1 — Geocerca País (FUERA_DE_PAIS): Toda lectura fuera del cuadrante de México (lat fuera de 14.0° a 33.0° o lng fuera de -118.5° a -86.0°, incluyendo coordenadas 0, 0) se marca como esAnomalo = true y su odómetro se descarta (kmValidado = null).
  • Filtro 2 — Velocidad Implícita (VELOCIDAD_IMPOSIBLE): Si la distancia Haversine entre el punto anterior y el nuevo dividida entre el tiempo transcurrido supera 180 km/h, el punto se marca como anómalo y se excluye de kmValidado y de Unidad.kmOficial.
  • Filtro 3 — Salto Lineal (SALTO_DISTANCIA): Si entre dos lecturas sucesivas hay una distancia lineal mayor a 300 km sin lecturas intermedias, se marca como anómalo. Requisito para el proveedor: Cuando un vehículo recupere cobertura celular y descargue puntos guardados en memoria (buffer), la plataforma del proveedor debe entregarlos en orden cronológico con sus timestamps originales para no provocar falsos saltos de distancia o velocidad.
  • Detección de Huecos de Señal (HuecoSenalGPS): Si entre la lectura previa y la actual de una unidad transcurren más de 15 minutos, Orión crea automáticamente un registro de pérdida de señal. Por lo tanto, la frecuencia de reporte de unidades en movimiento debe ser ≤ 5 a 10 minutos (idealmente de 1 a 5 minutos).

4.2 Módulo D — Cálculo de Combustible, Rendimiento y Sobrellenado

Orión utiliza las lecturas de odómetro validado (PosicionGPS.kmValidado) para auditar cada carga de combustible:

  • Búsqueda de odómetro al momento de la carga: Para cada carga registrada, Orión busca la lectura GPS válida inmediatamente anterior o igual a la fecha/hora de la carga, exigiendo que la lectura no tenga más de 48 horas de antigüedad.
  • Cargas sin hora (importadas por día): Cuando un archivo de proveedor de combustible solo trae fecha, Orión toma el odómetro GPS al inicio del día (00:00 hrs México, UTC-6) y el odómetro más alto del cierre de ese día para validar el rango mínimo y máximo que pudo recorrer la unidad.
  • Alertas automáticas: Con el kilometraje GPS entre cargas se calcula el rendimiento real (km/L), el nivel estimado del tanque antes de cargar (que también se muestra en el mapa en vivo) y se disparan las alertas de Sobrellenado (exceso > 15% de la capacidad del tanque) y de Discrepancia Km ≠ GPS (cuando el odómetro capturado manualmente difiere > 15% y ≥ 50 km respecto al GPS).

4.3 Módulo E y Alertas — Triangulación TAG / Combustible / GPS

Orión ejecuta tres cruces automáticos de auditoría sobre los últimos 7 días de operación:

  • TAG sin GPS cercano: Por cada cobro de caseta (IAVE, PASE, TeleVía), Orión verifica que exista al menos una lectura en PosicionGPS para esa unidad dentro de una ventana de ±60 minutos alrededor de la hora del cruce.
  • Combustible sin actividad: Verifica que el día calendario en que una unidad reporta una carga de combustible tenga al menos un punto GPS o cruce de TAG registrado en ese mismo día.
  • Unidad activa sin señal GPS: Detecta unidades activas disponibles cuya última lectura en PosicionGPS tenga más de 48 a 72 horas. Por ello, las unidades estacionadas deben emitir al menos un reporte periódico de estado (heartbeat cada 6–12 horas) para confirmar que su GPS sigue operativo.

4.4 Módulo A.1, Mantenimiento (C) y Reporte Ejecutivo de Estatus de Flota

  • Movimiento real para Checklists Semanales: Tanto el módulo de Checklists como el Reporte Ejecutivo de Estatus de Flota determinan qué unidades estuvieron en operación verificando que MAX(kmValidado) - MIN(kmValidado) ≥ 1 km en el periodo.
  • Mantenimiento Preventivo: Cada vez que entra una lectura válida con odómetro acumulado, Orión actualiza Unidad.kmOficial, disparando los avisos de servicio preventivo cada 5,000 km.

5. Matriz de Evaluación Técnica para Proveedores Candidatos (RFP)

Todo proveedor candidato debe responder y entregar evidencia técnica de los siguientes 10 puntos antes de realizar pruebas de integración con Orión:

# Requerimiento Técnico de Integración Carácter Pregunta / Entregable Solicitado al Proveedor Cumple (Sí / No / Evidencia)
1 Documentación de API y Sandbox Indispensable ¿Cuentan con documentación OpenAPI / Swagger o colección de Postman y credenciales de prueba?
2 Consulta Masiva (Batch) o Webhooks Indispensable ¿Su API permite consultar el estatus de toda la flota (~116 unidades) en una sola llamada HTTP, y/o enviar Webhooks HTTP POST en tiempo real?
3 Entrega de Odómetro Acumulado Indispensable ¿Cada registro de posición en la API/Webhook incluye el odómetro acumulado total del vehículo (en km)?
4 Timestamp Real de Lectura GPS Indispensable ¿El timestamp entregado corresponde al instante real de la lectura del GPS en UTC (sin alterarse cuando la unidad está estacionada)?
5 Frecuencia de Actualización (≤ 10 min) Indispensable ¿Cuál es el intervalo de actualización en ruta (ej. 1–5 min) y cada cuánto reporta una unidad estacionada (heartbeat)? (Requerido < 15 min en ruta).
6 Mapeo de Identificador de Unidad Indispensable ¿Qué identificador único expone la API (ID inmutable, placa, VIN o campo para guardar nuestro numeroEconomico)?
7 Consulta de Historial por Rango de Fechas Indispensable ¿Cuentan con endpoint para recuperar el historial de puntos de una unidad entre dos fechas (para rellenar lecturas ante cortes)? ¿Cuántos meses conservan?
8 Estado del Motor y Horómetro Deseable / Fase 2 ¿La API entrega el estado de ignición (encendido/apagado) y las horas acumuladas de motor (horómetro para grúas)?
9 Límites de Tasa (Rate Limits) y Costo de API Indispensable ¿Cuál es el límite de peticiones por minuto/hora permitido y se confirma que el uso de API/Webhooks está incluido sin costo por llamada?
10 SLA de Disponibilidad de Plataforma Indispensable ¿Cuál es el SLA de disponibilidad mensual garantizado para la API/Webhooks (objetivo ≥ 99.8%)?
🔌 Proceso de Pruebas de Conexión con Orión

Para validar técnicamente a los proveedores finalistas, Grupo Kabat solicitará acceso temporal a un endpoint de prueba (o muestra real de payload JSON de sus endpoints de estatus masivo e historial) para verificar que los campos 1 al 7 cumplan con el contrato de datos descrito en la Sección 3 de este documento.
